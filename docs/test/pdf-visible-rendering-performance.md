# 可见页面优先：PDF 底图与框选性能对照

2026-10-29。该改动对应 PDF 性能分析中的任务调度方向；与[旧批注中的重复原生链接](../bug_fix/pdf-native-link-duplicates.md)是两个独立问题。

## 改动与取舍

Scroller 为滚动缓冲区挂载邻页。旧版 `AgenteroRenderLayer` 挂载后立即生成每张整页底图；引擎把 `renderPage` 排为 CRITICAL，而高清瓦片和用户框选的 `renderPageRect` 为 HIGH。在单 worker 上，屏外重页因此先于可见瓦片与框选运行。

现在通过已有页面壳的 IntersectionObserver 可见性控制底图请求。页面进入视口才请求底图，离开时中止尚未完成的请求；已有 pinned 底图仍可显示，缓存、分辨率、旋转与上游瓦片生命周期保持原策略。不支持 IntersectionObserver 时仍按旧行为渲染。

这取消了屏外整页底图预取，首次滚到未缓存页面时才生成该底图；高清瓦片仍由上游按视口请求。正在 worker 内执行的同步光栅不能被强制抢占；该改动减少提前入队的任务，没有替换上游队列。参考 [PDF.js 的 visible pages / detail views 优先策略](https://github.com/mozilla/pdf.js/blob/master/web/pdf_rendering_queue.js)，复用浏览器可见性能力实现此处局部控制。

## 实测条件与结果

Chrome 154 / macOS、DPR=2，真实 PdfViewer，固定 740×900 阅读区，缩放约 85.3%。AgentCompass `2607.13705` 使用真实 PDF 与原 19,808 条 sidecar 的内存副本，两个条件均已启用批注判重与 512px 瓦片。浏览器的内存 sidecar 读取先于原生批注加载，所以上游延后执行导入时两个条件实际都创建 206 条；它与完整桌面文件读取较慢、能提前比较原生链接而只创建 8 条的时序不同。保存侧始终压成 206 条，避免继续增长。每次重载页面并打开新 engine，等待全部已发起任务结束；先运行可见性条件三次，再恢复旧代码运行三次。未把同一结果重复计数为更多轮次。

计时从 `openDocumentBuffer` 发起开始。瓦片完成指 BMP Task 返回；图片 load 单列记录，不等同于 GPU 实际呈现时刻。数值是本机样本对照，不是跨平台性能保证。

| 指标（ms） | 缓冲页全部生成底图 | 仅可见页生成底图 |
| --- | --- | --- |
| 首张图片 load，三次 | 268 / 249 / 231 | 267 / 248 / 242 |
| 第 1 页最后瓦片 Task 返回，三次 | 1872 / 1762 / 1772 | 291 / 280 / 274 |
| 第 1 页最后高清图片 load，三次 | 1875 / 1764 / 1773 | 293 / 284 / 292 |
| 初始底图请求页（从 0 开始） | 0、1、2、3 | 0、1 |

首张图片耗时没有显著改善；首屏高清瓦片 Task 完成的中位数从 1772ms 降到 280ms，约减少 84%。图片 load 中位数从 1773ms 降到 292ms。

另做一次交互对照：重载后等待首张图片，立即用实际鼠标事件点「视觉批注」，在第 1 页相同位置拖框，等待备注编辑器出现。旧版 PNG 裁剪 Task 为 1384ms，改动后为 18ms。这个值包含排队、渲染与编码，不包含用户拖动；它是打开期间的单次排队对照，不代表所有区域的固定裁剪耗时。第 3 页重图在闲置后的原生 WebKit 裁剪为 176ms，测量条件不同，不与此处 18ms 混算。

## 验收与边界

- 三份 PDF（AgentCompass、中文 Harbor 报告、TRACE）首屏与第 3 页完成出图，截图检查未见缺块、白缝或文字清晰度下降。截图不提交到仓库。
- AgentCompass 连续跳页再返回、框选后打开备注编辑器通过；旧批注中的 8 条高亮保留。备注保存与重开、链接导航和缩放分别按实际阅读器流程验收。
- 全套改动的类型检查、相关批注 / 瓦片生命周期 / 旋转回归通过。临时性能采集与测试界面不进入产品代码。
- 已用完整 Tauri 开发应用启动此可见性方案，观察到底图与瓦片返回；后续原生交互验收因 Mac 锁屏中断。因此本表只报告 Chromium A/B，不宣称原生 WebKit 已得到相同的 84% 收益，也不宣称 Windows / Linux 通过。

已检查开发目录，无独立 Roadmap / TODO。剩余项在 PDF 能力文档维护：解锁后补齐此方案的完整原生交互验收；合法的大量不同批注、复杂重页的同步光栅及跨平台滚动仍需按各自样本评估。文字几何 / text runs 在本次原生追踪中单项主要约 20–30ms，未取得支持进一步改写的显著收益证据，保留现有延迟与缓存策略。
